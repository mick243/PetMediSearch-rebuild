# 매일 18:40 — 작업 진행 상태 점검과 SSOT 갱신

루트 `SSOT.md` 는 "지금 상태" 의 단일 출처다. 손으로 기우다 보면 어디까지가 언제 것인지 알 수 없게 되므로, **하루에 한 번 정해진 시각에 통째로 다시 재서** 맞춘다.

## 언제 하나

- **매일 오후 6시 40분(KST)** 에 한 번.
- 그 시각에 세션이 열려 있으면, 지금 하던 단계를 끊지 말고 마무리한 뒤 바로 이어서 한다. 시작할 때 사용자에게 한 줄로 알린다.
- 그 시각에 세션이 없었다면 **그날 18:40 이후 처음 시작되는 세션**이 대신 한다. 사용자가 다른 일을 시켰다면 그 일을 먼저 끝내고 한다.
- 스케줄 태스크가 이 규칙을 수행하러 띄운 세션이면 곧바로 시작한다.
- **이미 했는지는 `SSOT.md` 첫머리의 `기준 시각` 날짜로 판단한다.** 오늘 날짜면 다시 하지 않는다.

## 1단계 — 진행 상태를 잰다 (문서를 믿지 않는다)

수치는 어느 문서에서도 옮겨 적지 않고 매번 직접 잰다. 아래를 전부 돈다.

1. **커밋** — `git log --all --since="<마지막 기준 시각>" --format="%h %ad %d %s" --date=short`. `main` 에 들어온 것과 다른 브랜치에만 있는 것을 나눈다.
2. **원격 동기** — `git fetch` 없이 `git rev-list --left-right --count main...origin/main` 로 로컬 main 이 앞선지 뒤처졌는지 본다. 이 저장소는 GitHub(`mick243/PetMediSearch-rebuild`)에 원격이 있고 **PR 로 병합된 것이 로컬에 안 들어와 있는 일이 실제로 있었다**(2026-09-22 에 2커밋 뒤처져 있었음). `git pull` 은 하지 않는다 — 상태만 적는다.
3. **미커밋** — `git worktree list` 로 **모든 워크트리**를 돌며 `git status --short` 와 오늘 mtime 인 파일을 본다. 커밋만 보면 놓친다. 이 저장소에는 **방치된 미커밋이 실제로 쌓여 있다**(`project-ui-ux-review-eedd45` 50건).
4. **브랜치** — 브랜치마다 `git rev-list --left-right --count main...<브랜치>` 로 main 대비 앞·뒤 커밋 수를 재고, 병합 완료·병합 대기·손대지 말 것(미커밋 있음)으로 가른다.
5. **개발 DB 실측** — `SSOT.md` 부록 B 의 명령으로 시설 · 계정 · 글·댓글 · 후기 · 즐겨찾기 · 반려동물·접종 일정 수와 `SHOW TABLES` 를 조회한다. DB 는 MySQL 8 이고 Docker 로 뜬다(`docker compose up -d db`). **DB 를 띄우지는 않는다** — 떠 있지 않으면 조회를 건너뛰고 `(미재측 · Docker 정지)` 로 적는다. 읽기 조회만 한다.
6. **테스트** — `server/` 에서 `node --test` 를 돌려 통과·실패 수를 잰다. 실패가 있으면 **원인이 코드인지 환경인지**(모듈 누락·DB 없음) 한 줄로 가른다. `client/` 에는 테스트 스크립트가 없다. 빌드는 하지 않고 `npm install` 도 하지 않는다.

## 2단계 — SSOT.md 를 갱신한다

- **첫머리**: `기준 시각` 을 오늘로 바꾼다. 그 아래 갱신 로그에 `**YYYY-MM-DD 갱신** — 한 줄 요약. §n · §m 반영` 한 줄을 **맨 위에** 더한다. 이전 갱신 줄은 지우지 않는다.
- **매번 다시 재는 절**: §0 30초 요약(세 가지 사실 · 다음 한 걸음) · §2 브랜치와 워크트리 표 · §4 데이터 실측 · §5 기능 현황 · §7 품질(테스트) · §8 리스크와 미해결 · §9 다음 작업. 나머지 절은 오늘 바뀐 것이 있을 때만 고친다.
- **해결된 항목은 지우지 않는다.** ~~취소선~~ 을 치고 `✅ 해결 YYYY-MM-DD` 와 근거 한 줄을 남긴다.
- **잰 수치만 적는다.** 오늘 재지 못한 수치는 옛 값 옆에 `(YYYY-MM-DD 값 · 미재측)` 을 붙인다.
- 절 번호와 구조는 바꾸지 않는다. 표의 열도 바꾸지 않는다.
- 다른 워크트리의 미커밋 작업은 **상태만 기록**한다. 파일을 열어 보되 고치거나 커밋하거나 지우지 않는다.

## 3단계 — 보고하고 커밋한다

- **사용자에게 보고**: ① 오늘 바뀐 것(커밋 · 원격 동기 · 미커밋 · 데이터 · 테스트) ② SSOT 어느 절을 어떻게 고쳤나 ③ 사용자 결정이 필요한 것(pull · 병합 · 삭제 · 방치된 작업). 짧게, 표는 하나까지.
- **커밋은 `SSOT.md` 만 담아 하나**로 한다. 메시지는 `SSOT — YYYY-MM-DD 갱신 · <한 줄 요약>`. 다른 변경을 섞지 않는다. **push 는 하지 않는다.**
- 세션이 워크트리(별 브랜치)에 있으면 그 브랜치에 커밋하고, main 에 넣을지는 보고에 적는다. main 체크아웃에 있으면 main 에 바로 커밋한다.

## 하지 않는 것

- DB 쓰기 · 스키마 적용(`alter*.sql` · `createTables.sql`) · `importData.js` · `createAdmin.js`. 조회만 한다.
- `git pull` · `git push` · 브랜치 병합 · 삭제 · 워크트리 정리. 필요하면 §9 에 제안으로만 적는다.
- `npm install` · 빌드 · 서버 기동. 테스트만 돌린다.
- 문서에 적힌 숫자를 다른 문서로 옮겨 적기. 정본은 DB 조회와 git 이다.
- 갱신을 미루기 위해 "바뀐 게 없다" 고 단정하기. 바뀐 게 정말 없어도 기준 시각과 갱신 로그 한 줄은 올린다.
