# 출시 전 전체 점검 (2026-09-13)

서비스 개시가 가능한 상태인지 보기 위해 전체를 점검한 기록입니다. 고친 것은
없습니다 — **무엇을 고쳐야 하는지의 목록**입니다.

점검 방법은 세 가지를 겹쳐 썼습니다.

1. 정적 검사 — 양쪽 린트·타입·테스트·빌드
2. 코드 정독 — 서버와 클라이언트를 각각 훑고 서로의 계약(경로·필드·응답 모양)을 대조
3. **실제 실행** — 브라우저에서 사용자가 하는 일을 그대로 하고, 의심스러운 것은
   API 로 직접 재현

아래 항목은 **"재현함"** 이라고 적힌 것만 실제로 확인한 것입니다. 코드만 읽고
판단한 것은 그렇게 표시했습니다.

## 요약

| 영역 | 상태 |
|---|---|
| 정적 검사 (린트·타입·테스트 61개·빌드) | 통과 |
| 핵심 기능 (가입→글·댓글·후기·반려동물·접종·즐겨찾기→탈퇴) | 통과 |
| 인증·권한 | **P0 #1 하나로 전면 무효** |
| 안정성 | **P0 #2 — DB 오류 한 건에 프로세스 종료** |
| 데이터 정확성 | **시각 9시간 오차, 별점 불일치** |
| 배포 구성 | 문서대로 하면 뜨지 않음 |
| 법적 고지 | `<Todo>` 미기입 + 코드와 4곳 불일치 |

**지금 상태로는 개시 불가입니다.** P0 3건은 합쳐서 반나절 분량이고, 그 뒤
P1 서버 항목까지 정리하면 소수 사용자 대상 베타는 열 수 있습니다.

## P0 — 개시 전 반드시

### 1. `/auth/social-login` 이 인증 없이 아무 계정의 토큰을 내줍니다

`server/routes/auth.js:16` → `server/controller/auth.js:112`

본문의 `{ socialId, socialType }` 을 그대로 믿고 그 사용자의 JWT 를 만듭니다.
카카오 id 는 숫자라 열거할 수 있고, 알면 그 사람으로 로그인됩니다.
`signupLimiter` 도 거치지 않아 계정을 무한히 만들 수 있습니다.

**재현함** — 아무 값이나 보냈더니 200 과 토큰, 계정까지 새로 생성.

```
POST /auth/social-login  {"socialId":"qa-forged-...","socialType":"kakao"}
→ 200 {"token":"eyJ...","user":{"id":22,...}}
```

클라이언트는 이 경로를 **어디에서도 쓰지 않습니다**(grep 0건). 라우트를 지우면
끝납니다. 남겨야 한다면 소셜 제공자에게 받은 액세스 토큰을 서버가 직접
검증해야 합니다.

### 2. 소셜 로그인 중 DB 오류 한 건이면 서버가 죽습니다

`server/controller/auth.js:156`

```js
if (error) reject(error);
resolve(results[0]);   // error 일 때 results 는 undefined → throw
```

`else` 가 없어서 오류일 때도 다음 줄이 실행됩니다. mysql2 는 콜백에서 난 예외를
잡아 같은 콜백을 한 번 더 부르고, 두 번째 예외는 잡아 줄 곳이 없어
`uncaughtException` 이 됩니다.

**재현함** — 같은 풀에 같은 모양의 코드로 없는 표를 조회했더니 프로세스가
`UNCAUGHT -> Cannot read properties of undefined (reading '0')` 로 종료.

같은 파일 `:210` 의 헬퍼는 `else` 가 있어 정상입니다. 이 한 곳뿐입니다.

### 3. 모든 시각이 9시간 어긋나 보입니다

| 실제(KST) | 화면 |
|---|---|
| 23:39 에 쓴 글 | `2026.09.13 14:39`, 목록엔 "9시간 전" |

**재현함** — DB 컨테이너가 UTC 입니다.

```
NOW() = 2026-09-13 14:40:06   UTC_TIMESTAMP() = 2026-09-13 14:40:06
호스트 = 2026-09-13 23:40:06 +0900
```

`created_at` 은 DB 기본값이라 UTC 로, `deleted_at` 은 Node 가 `new Date()` 로
넣어 KST 로 들어갑니다. **한 표 안에 두 시간대가 섞여 있습니다.**

compose 의 db 에 `TZ=Asia/Seoul` 과 `--default-time-zone=+09:00` 을 주는 쪽이
간단합니다. 이미 들어간 값의 보정도 함께 생각해야 합니다.

## P1 — 사용자가 실제로 겪는 것

### 서버

- **탈퇴한 계정의 남은 토큰으로 반려동물·즐겨찾기를 계속 추가할 수 있습니다.**
  **재현함** — 탈퇴 직후 옛 토큰으로 `POST /pets` → 200 `{"petId":9}`.
  글·댓글·후기는 `INSERT ... SELECT ... WHERE deleted_at IS NULL` 로 막았는데
  (`post.js`) `pets.js`·`favorites.js` 에 같은 처리가 없습니다.

- **없는 시설을 즐겨찾기하면 "추가했습니다" 라고 답합니다.**
  **재현함** — `POST /favorites/99999999` → 200, 목록에는 없음. `abc` 도 200.
  `INSERT IGNORE` 가 FK 위반까지 삼켜서 `favorites.js:42` 의 404 분기에 도달하지
  않습니다.

- **지워진 댓글에 답글이 달립니다.** **재현함** — 삭제된 41번을 부모로 보내
  200. 화면에는 안 보이는데 댓글 수에는 잡힙니다. 부모의 `post_id` 와
  `deleted_at` 을 보지 않습니다(`comment.js`).

- **참조 id 를 검증하지 않아 400 대신 500 이 납니다.** **재현함** — 없는
  `category_id`·`facility_id`·`post_id` 로 등록하면 모두 500 "서버 에러", 서버
  로그에는 FK 오류가 남습니다. 사용자는 무엇이 잘못됐는지 알 수 없습니다.

- **댓글을 수정하면 위치가 바뀝니다.** `comment.js:156`
  `SET content = ?, created_at = NOW()`. 목록이 `created_at ASC` 라 수정한 댓글이
  맨 뒤로 갑니다. `updated_at` 컬럼이 필요합니다.

- **회원 탈퇴가 트랜잭션 없이 6문장입니다.** `auth.js:350` 부근. 첫 문장(users
  닫기) 뒤에 실패하면 재시도가 "이미 탈퇴한 계정" 으로 막혀, 글·반려동물이
  영구히 남습니다. 풀이라 문장마다 커넥션이 달라 `getConnection` +
  `beginTransaction` 이 필요합니다.

- **`docker compose up -d` 가 README 대로 하면 실패합니다.** **재현함** —
  `${DB_PASSWORD:?...}` 치환은 `env_file` 이 아니라 셸이나 프로젝트 루트 `.env`
  를 봅니다.

  ```
  error while interpolating services.db.environment.MYSQL_ROOT_PASSWORD:
  required variable DB_PASSWORD is missing a value
  ```

  어제 배포 검증이 통과한 것은 제가 `--env-file server/.env` 를 붙였기
  때문입니다. README 와 compose 머리말을 고치거나 루트 `.env` 로 옮겨야 합니다.

- **compose 가 `TRUST_PROXY=1` 을 고정한 채 포트를 직접 공개합니다.** 앞에 nginx
  가 없으면 `X-Forwarded-For` 헤더 하나로 `req.ip` 를 바꿔 로그인 제한(15분
  10회)을 그냥 지나갑니다. `.env.example` 이 스스로 경고하는 상황을 compose 가
  기본으로 만들고 있습니다.

- **`GET /facilities` 를 파라미터 없이 부르면 8.9MB 가 나갑니다.** **재현함.**
  상한이 50,000 이고 일반 요청 제한이 분당 300회라, 주소 하나로 분당 2.7GB 를
  뽑아낼 수 있습니다. `/facilities/clusters?precision=99` 도 1.2MB 입니다.

### 클라이언트

- **글 등록 실패가 조용히 묻힙니다.** **재현함** — 본문에 한 글자 쓰고 지우면
  ReactQuill 이 `<p><br></p>` 를 남기고, 화면의 `content.length === 0` 검사를
  지나 서버가 400 을 줍니다. 알림 0건, 화면 그대로.
  `CreatePost.tsx:50` 의 `catch` 가 `console.error` 뿐입니다. 사진을 많이 붙여
  413 이 나도 같습니다. 게다가 axios 오류를 통째로 찍어 **요청 헤더의 토큰이
  콘솔에 남습니다**(지침 2.11 과 같은 부류).

- **별점이 화면과 다르게 저장될 수 있습니다.** **재현함** — 별 4개로 등록하면
  별은 4개로 남는데 문구는 "아주 좋아요"(내부 값 5)로 돌아갑니다. 그대로 다음
  후기를 쓰면 화면은 4점, 저장은 5점입니다. `Star.tsx:13` 이 `rating` prop 을
  초기값으로만 쓰고 이후 변화를 반영하지 않습니다.

- **후기 상세의 시각이 `26.09.13 14.09.SS` 로 나옵니다.** **재현함.**
  `ReviewBox.tsx:117` 의 `'YY.MM.DD HH.MM.SS'` — dayjs 에서 `MM` 은 분이 아니라
  월이고 `SS` 는 형식이 아니라 글자입니다. `HH:mm:ss` 여야 합니다.

- **후기 삭제에 확인창이 없습니다.** 글과 댓글에는 있습니다. 한 번의 오클릭으로
  사진이 붙은 후기가 사라지고, 되돌릴 방법이 화면에 없습니다.

- **`/createpost` 가 `LoginProtect` 밖에 있습니다.** 만료된 토큰으로 글을 다
  쓰고 등록하면 401 → 로그인 화면으로 하드 리다이렉트 → **작성한 글 전부
  유실**입니다.

- **지워진 글 상세에 댓글 입력창이 그대로 열립니다.** **재현함** — "게시글이
  존재하지 않습니다" 아래에 입력창과 등록 버튼이 남습니다. 서버도 삭제된 글의
  댓글을 받아 저장합니다.

- **후기 화면이 새로고침에 깨집니다.** 고른 시설이 Redux 에만 있어
  (`Review.tsx`) F5 하면 "검색된 결과가 없습니다" 가 됩니다. 마이페이지의 이동
  링크가 `<a href>` 라 매번 이 길을 탑니다 — 지침 4.7 위반입니다.

- **카카오 지도 SDK 로드가 실패하면 `/search` 전체가 "Error!" 화면이 됩니다.**
  (코드만 읽음 — SDK 번들까지 확인했으나 브라우저 재현은 못 함) 로더가 실패해도
  `<Map>` 이 그려지고, 그 안에서 `kakao is not defined` 가 나 라우트
  `errorElement` 로 떨어집니다.

## P2 — 눌러 보면 이상한 것

- 후기 목록이 작성자를 **"작성자 번호: 21"** 로 표시합니다 (재현함).
- 소셜 로그인을 취소하거나 실패하면 아무 안내 없이 `/login` 으로 돌아갑니다.
- `/category` 조회가 실패하면 게시판이 영원히 "불러오는 중" 입니다.
- `localStorage` 의 사용자 JSON 이 깨져 있으면 **첫 화면부터 흰 화면**입니다
  (`localStorage.ts` 의 `JSON.parse` 에 try/catch 없음, 모듈 로드 시점에 실행).
- 즐겨찾기·일정 화면에서 로그아웃하면 "로그인이 필요한 서비스입니다" 경고가
  뜹니다. `Menu.tsx` 가 `/myprofile` 만 처리합니다.
- 마이페이지 후기가 `SELECT *` 라 사진 JSON 을 통째로 내려보냅니다
  (`mypage.js:118` — 바로 위 주석이 그러지 말라고 적혀 있습니다).
- `pets.photo` 에 크기·형식 검증이 없습니다. 후기 사진에는 있습니다.
- 소셜 첫 로그인 응답의 `socialType` 이 빈 문자열이라, 재로그인 전까지
  마이페이지에 제공자 아이콘이 뜨지 않습니다.
- `JWT_SECRET` 이 비어 있어도 서버가 그냥 뜹니다. 모든 로그인이 500 인데
  `/health` 는 200 입니다. 시작할 때 확인하고 멈춰야 합니다.
- 없는 주소로 들어가면 "Error!" 만 뜨고 설명이 없습니다.
- **옛 `server/public/search.html` 이 아직 `/search` 로 서빙됩니다.** 네이버 지도
  `YOUR_CLIENT_ID` 가 박힌 예전 화면입니다. 지워야 합니다.
- 개인정보처리방침이 코드와 어긋나는 곳 4가지 — ① 주소를 "지역 맞춤 안내" 용도로
  필수 수집한다고 적었지만 코드는 저장만 하고 쓰지 않습니다 ② "소셜 로그인은
  이메일을 수집하지 않습니다" 인데 구글 버튼이 `scope=email profile` 을 보냅니다
  ③ "마이페이지에서 자신의 개인정보를 확인" 한다고 했지만 그 화면이 없습니다
  ④ 제3자 표에 jsDelivr(폰트 CDN)가 빠져 있습니다.

## 확인하지 못한 것

- **지도 첫 진입.** 점검에 쓴 브라우저 창이 화면을 그리지 못하는 상태여서,
  지도가 `swLat=-4835, swLng=4655137` 같은 좌표로 조회하고 시설 수가 "-" 로
  남는 것이 **지도 버그인지 그 환경 탓인지 가르지 못했습니다.** 실제 브라우저에서
  `/search` 첫 진입에 시설이 뜨는지 확인이 필요합니다.
- **소셜 로그인 실제 왕복.** 서버 `.env` 에 `KAKAO_CLIENT_ID`·`NAVER_*`·
  `GOOGLE_*` 가 없고 클라이언트 쪽도 네이버·구글 키가 비어 있어(버튼 링크에
  `client_id=` 가 빈 채로 나갑니다) 개발 환경에서는 검증 자체가 불가능합니다.
- HTTPS 로 배포했을 때 카카오 지도 타일의 mixed content 여부.
